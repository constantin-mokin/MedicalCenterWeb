# Медицинский центр «Искра»

Информационная система медицинского центра (г. Минск, Беларусь).
Версия 2.2 — устранены все 24 замечания аудита кода, исправлен график
статистики (надписи «undefined»), проект наполнен демонстрационными данными,
приближенными к реальности: расписание заполнено до 13 ноября 2026 года;
администратору открыт полный доступ к медицинским картам; адрес клиники
удалён из интерфейса.

## Технологии

| Компонент | Решение |
|---|---|
| Платформа | ASP.NET Core 9 (MVC, C# 12) |
| База данных | SQLite + Entity Framework Core 9 (миграции) |
| Аутентификация | Cookie-схема, 3 роли: администратор, врач, регистратор |
| Интерфейс | Razor Views, собственный CSS, тёмная тема, адаптивная вёрстка |

## Запуск

```bash
dotnet run
```

При первом запуске автоматически применяются миграции, создаётся база
`medical_center.db` и наполняется демонстрационными данными.

Требуется .NET 9 SDK. Для обновления схемы после доработок моделей:

```bash
dotnet ef migrations add <НазваниеМиграции>
```

**Важно:** если рядом лежит база от старой версии проекта — удалите файл
`medical_center.db`, при запуске будет создана новая. Именно так активируются
обновлённые демонстрационные данные (заполнение до 13.11.2026).

## Демонстрационные данные (Минск)

- **6 врачей** — кардиолог, невролог, терапевт, офтальмолог, эндокринолог,
  оториноларинголог; белорусские имена, биографии, неделимое недельное расписание;
- **13 процедур** с ценами в BYN на уровне частных клиник Минска
  (от 15,00 BYN за тонометрию до 85,00 BYN за суточное мониторирование ЭКГ);
- **12 пациентов** — белорусские имена, мобильные номера +375 (МТС/A1/life:),
  адреса электронной почты доменов yandex.by, gmail.com, mail.ru;
- **~350 приёмов**: выполненные за 15 недель (с медкартами и реалистичными
  диагнозами и рекомендациями), отменённые по неявке и запланированные
  **вплоть до 13 ноября 2026 года** включительно — расписание заполнено
  вперёд на 7+ недель;
- **222 медкарты** выполненных приёмов; **23+ записи журнала аудита**
  (регистрации пациентов, записи на приём, отметки выполнения, сброс пароля).

Даты приёмов вычисляются относительно дня первого запуска: история выполненных
приёмов охватывает 15 недель, запланированные приёмы заполняют календарь
до 13 ноября 2026 года (если приложение запущено позже этой даты — ближайшие
3 недели), поэтому панель «Приёмы на сегодня», графики и фильтры всегда
показывают осмысленные данные.

Все данные вымышлены; совпадения с реальными людьми случайны.

## Что исправлено (по замечаниям)

### Критические (1–5)

1. **HomeController создан.** `UseExceptionHandler("/Home/Error")` теперь ведёт
   на существующую страницу; добавлена страница «Доступ запрещён»
   (`AccessDeniedPath`) и обработка кодов состояния 404/500.
2. **IDOR в отметке приёма закрыт.** `DoctorController.MarkCompleted`
   проверяет, что приём принадлежит текущему врачу; чужой приём → «Доступ запрещён».
3. **IDOR в медкартах закрыт.** `MedicalRecordController.Edit/Save` проверяют
   принадлежность приёма врачу (администратор сохраняет полный доступ).
4. **Удаление врача с приёмами блокируется** понятным сообщением вместо
   исключения FK и ошибки 500 (то же для процедур).
5. **История пациента защищена.** Приёмы пациента больше не удаляются каскадом
   (`Restrict` в модели данных); удаление пациента с приёмами блокируется;
   дубликат телефона обрабатывается дружелюбным сообщением.

### Средние (6–15)

6. **N+1 устранён**: валидатор записи загружает приёмы только одного дня и
   одним запросом с `Include(Procedure)`.
7. **Сортировка расписаний** — по дню недели, затем по времени (SQLite не
   транслирует ORDER BY по TimeSpan, поэтому вторичная сортировка в памяти).
8. **Пагинация защищена**: `page < 1` нормализуется до 1 во всех списках.
9. **Редактирование приёма доступно из интерфейса**: модальное окно «Изменить»
   в списке приёмов (ранее `UpdateAppointment` был недостижимым кодом).
10. **Редактирование расписания доступно из интерфейса**: кнопка «Изменить»
    в таблице расписаний (ранее `Update` был недостижимым кодом).
11. **Годовой график группируется по месяцам** (12 столбцов вместо 365),
    недельный и месячный заполняются нулями за пустые дни.
12. **Фильтр дат строгий**: «до» включает выбранный день, но исключает полночь
    следующего.
13. **Аудит расширен и асинхронен**: фиксируются отметка выполнения приёма,
    сохранение медкарт, изменения расписаний, сброс пароля; добавлена очистка
    журнала старше 90 дней.
14. **Генерация паролей** использует криптостойкий `RandomNumberGenerator`
    вместо `System.Random` (гарантируются заглавная, строчная буквы и цифра).
15. **Политика паролей усилена** (минимум 8 символов, регистр и цифра) и
    добавлен **сброс пароля администратором** на новой странице «Пользователи».

### Незначительные (16–24)

16. **Nullable reference types включены** по всему проекту, предупреждений нет.
17. **ViewBag заменён типизированными моделями представлений**
    (15 моделей в `Models/ViewModels.cs`).
18. **Модели снабжены DataAnnotations** (Required, StringLength, Phone,
    EmailAddress, Range).
19. **Строка подключения перенесена** в `appsettings.json`.
20. **Схема БД создаётся миграциями** EF Core вместо `EnsureCreated`
    (каталог `Migrations`).
21. **Файлы базы данных исключены** из проекта и репозитория (`.gitignore`).
22. **Единый источник времени** `AppClock` (Europe/Minsk, UTC+3) вместо
    рассыпанных вызовов `DateTime.Now`.
23. **Цена фиксируется в момент приёма** (`Appointment.RecordedPrice`);
    выручка считается по зафиксированным ценам.
24. **Инфраструктура локализации**: общие строки оболочки вынесены в
    `Resources/Strings.resx`, установлена культура ru-RU по умолчанию,
    тексты статусов дедуплицированы в методах расширения.

### Дополнительно найденные и исправленные дефекты

- **AdminController был доступен всем ролям** (стоял `[Authorize]` без ролей) —
  теперь только администратору.
- **Формы удаления расписания, создаваемые в JavaScript, не работали**:
  `asp-action` не обрабатывается внутри строк скрипта — заменены на обычные
  URL с корректным antiforgery-токеном.
- **Маршрут по умолчанию** `{controller=Auth}/{action=Login}` ломал адреса
  вида `/Admin` (404) — заменён на стандартный `{controller=Home}/{action=Index}`
  с перенаправлением на панель соответствующей роли.
- **Логины генерируются с транслитерацией** кириллицы (например,
  «марина.савицкая» → «marina.savitskaya»).
- **График «Приёмы по периодам» показывал «undefined»**: JavaScript читал
  свойства `Date`/`Count`, а ASP.NET Core сериализует JSON в camelCase
  (`date`/`count`) — подписи осей и значения столбцов не отображались.
- **Даты seed-данных «смешивали недели»**: расчёт «прошлый понедельник»
  относительно дня запуска мог дать понедельник текущей недели, а
  «прошлая суббота» — из предыдущей; теперь прошлая неделя вычисляется
  целиком как календарная, без пересечений с историей и будущими приёмами.
  Будущие приёмы не ставятся в уже прошедшие слоты времени.

## Изменения версии 2.2

- **Администратору открыт полный доступ к медицинским картам** — те же
  действия, что у врача: на странице «Приёмы» появились кнопки «Выполнен» и
  «Медкарта» (кнопка «Выполнен» только для запланированных приёмов),
  в истории пациента — ссылка «Открыть карту», на главной панели — карточка
  «Медкарт» и столбец «Медкарта» в последних записях. Все действия админа с
  медкартами и отметками приёмов фиксируются в журнале аудита. Регистратор
  по-прежнему не имеет доступа к медицинским данным.
- **Адрес клиники удалён** из подвала каждой страницы и с экрана входа —
  проект больше не содержит адреса.
